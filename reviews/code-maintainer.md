# Code review: maintainer lens (Okoye)

Verdict: sound, well-tested core (26 tests pass) with clean separation of math and UI, but two input-handling gaps would bite real users and the 500-line Tool.astro is the next maintenance cost. Must-fix: 2.

Template leftovers (already on the fixer's list, not repeated): README template text, scripts/new-tool.sh, duplicate legal links, build-date "Last updated", British spelling.

| Severity | file:line | Finding | Why | Fix |
|---|---|---|---|---|
| must | src/lib/splits.js:147-153, src/components/Tool.astro:297-298 | `intervals()` has no cap on `repM / lap`. Custom repeat distance 400000 m gives 1,000 "inside" splits and a 20 KB note. 1e9 m on a 50 m lap loops 2e7 times (about 4 s here) and builds a multi-hundred-MB string. | Typing one extra zero, or pasting a wrong number, can freeze the tab. `raceSplits` has MAX_ROWS; intervals does not. | Reject when `Math.ceil(repM / lap) > MAX_ROWS` or `repM > 1e5`; also cap the "Splits inside a repeat" text at about 12 entries. |
| must | src/lib/splits.js:28-32 | `parseNumber` turns a comma into a decimal point. "10,000" becomes 10. Tested live: custom distance "10,000" gives a 10 m race, "33:20:00.0 per km". | US users type thousands commas. The page itself prints "10,000 m". Silent wrong answer. | Treat `^\d{1,3}(,\d{3})+$` as thousands; treat a single comma with 1 or 2 digits after it as a decimal. Add tests. |
| should | src/components/Tool.astro (whole file, 500 lines) | Markup, 40 lines of CSS and 280 lines of TypeScript in one file. `compute()` is 105 lines and builds display strings and copy text together. | Hard to test: UI logic (labels, notes, band text) has zero tests. Only `splits.js` is covered. | Move `compute()` into `src/lib/view.js` (pure, returns the View object) and add 5 known-answer tests on its strings. |
| should | src/components/Tool.astro:250-260 | `restore()` accepts any string up to 19 chars into every field, then does not re-validate selects. A bad `cunit` (from old or edited storage) sets the select to "" and `distanceM()` returns NaN (`NaN && ...` is falsy, so `n && n>0` returns NaN, not null). The `D === null` guard is bypassed and the user sees a generic message with no field marked. | Storage schema is `track-split-v1` but there is no migration path; any future option rename breaks returning users. | Validate each select value against its options; make `distanceM()` return null unless `Number.isFinite`. |
| should | src/components/Tool.astro:440-441 | Table header and cell classes come from a nested ternary (`i > 0 && (i === last \|\| v.head.length === 3 \|\| i > 1)`). | Adding a column changes alignment in non-obvious ways. | Put an `align` array in the View object. |
| should | src/components/Tool.astro:440-444 | `innerHTML` is used with strings from our own code (safe today). The custom distance text is not in any cell, so no user text reaches innerHTML now. | One future change (echoing the user's input in a cell) becomes HTML injection. | Add a one-line comment "values are numbers formatted by us; never put raw input here", or build rows with `textContent`. |
| should | src/lib/splits.js:121-124 | `raceSplits` rejects `time > MAX_TIME` but `intervals` and the "lap to finish" path do not check pace sanity. Goal "1200" (minutes) shows "1:36:00.0 per lap" with no warning. | Users who type seconds get 20-hour answers that look valid. | Warn when pace is slower than 20:00 per mile or faster than 2:00 per mile ("Check the time: it is 20 hours"). |
| should | tests/splits.test.mjs | No test for: comma decimals in `parseTime` ("1:36,5"), `from: 'line'` with a negative split, `intervals` with `rest` 0 and one rep, `markers` with float distances (mile), step 1 on a mile (the "1:00" lap). | These are the paths where rounding and floats can regress. | Add 6 tests (cases listed in code-regression.md). |
| should | src/pages/robots.txt.ts:3-6, astro.config.mjs | On the GitHub Pages build, robots.txt says `Allow: /` and links the Pages sitemap, while pages carry noindex. It is harmless but contradictory. | Mixed signals if someone later removes the meta tag. | Emit `Disallow: /` when `BASE_URL` is not `/`. |
| nice | public/_headers | The two pages.dev rules are correct for Cloudflare Pages. No test guards them. | A copy-paste from another tool could drop them. | Add a tiny test that greps `_headers` for `X-Robots-Tag: noindex`. |
